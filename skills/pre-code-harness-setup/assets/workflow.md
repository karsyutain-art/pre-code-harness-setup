# Workflow: <기능 이름>
노드는 "단계"이지 task가 아니다. 구현 계획이 있으면 구현 노드에는 계획 파일 경로만 적는다.
규칙으로 판정 가능한 일(금칙어, 스키마 검사, 숫자 검산)은 AI가 아니라 코드에 맡긴다.

## 노드
| ID | 단계 | 담당 | 입력 | 출력(→ PROGRESS.md) | 완료 판정 |
|---|---|---|---|---|---|
| N1 | 요구사항·합격 테스트 작성 | AI | 사용자 요청 | tests/acceptance/* | 테스트가 '실패'로 실행됨 |
| N2 | 구현 (task는 계획 파일 참조) | AI | N1, 계획 | 코드 | .harness/checks.sh 통과 (Stop Hook) |
| N3 | 검수 | reviewer | N2 diff | 검수 목록 | 심각 0 |
| N4 | 스테이징 배포 | 코드(스크립트) | N3 통과 | 스테이징 URL | 헬스체크 200 |
| N5 | 승인 | **사람** | 스테이징 URL | 승인/반려 | 사용자 응답 |
| N6 | 운영 배포 | 사람 실행 또는 승인 후 스크립트 | N5 승인 | — | — |

## 엣지
- N1 → N2 → N3 (고정)
- N3 실패 → **N2로만** 복귀 (재시도 최대 3회, 초과 시 중단하고 보고)
- N3 통과 → N4 → N5
- N5 반려 → 반려 사유를 PROGRESS.md에 적고 N2로
- N5 승인 → N6

## 상태 (PROGRESS.md에 기록)
현재 노드, 노드별 결과, 재시도 횟수, 검수 지적사항, 승인 여부

## 사람 승인이 필요한 지점
돈이 나가는 일 · 외부로 발송되는 일 · 운영 배포 · 데이터 삭제 — AI가 혼자 진행하지 않는다.
